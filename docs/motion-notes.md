## 二、下指令的格式

不要只說「做一個很酷的動畫」。至少給這些：

```text
主題／一句話訊息：
長度：15–20 秒最好；有旁白就依旁白長度決定
核心效果：只選 1 個主效果，最多再加 1 個輔助
視覺方向：底色、主色、強調色、字體；或直接說「交給你」
分鏡表：時間 | 畫面發生什麼 | 畫面文字 | 轉場
結尾：帳號、最後一句話
聲音：要不要音效／配樂／旁白
```

分鏡裡寫「畫面發生什麼」就好，不用寫技術名詞。

## 三、做「家庭責任流」學到的事

### 視覺：怎麼避開 AI 感、廉價感

第一版用深藍底＋橘藍發光，被評為廉價、有 AI 感。問題出在：

1. 深藍加發光是 AI 生成科技畫面最常見的配色
2. 每個元素都發光，沒有主次
3. 只用一種粗黑體，沒有字體對比
4. 背景是空的漸層，沒有材質
5. 每個動作的節奏都一樣

改成「紙與墨」後質感明顯提升，做法：

- **材質**：程式產生的紋路紙（纖維、雜點、不均勻光），加上每秒跳 12 次的顆粒，像定格印刷
- **限色**：墨黑為主，一個強調色（朱紅）代表重點；第二個顏色（群青）留到故事轉折才第一次出現
- **印刷語言取代發光**：網點、木刻斜線、印章、套色錯位的陰影
- **字體對比**：標題用粗襯線（思源宋體 Black），標籤用細黑體
- **節奏**：重擊、回彈、震動有輕有重，標題分行錯開出場

### 開頭鉤子

- 第一格就是 IG 封面，要當海報設計：大字提問＋畫面已經在動，不要從黑畫面淡入
- 有效組合：**提問 → 視覺斷裂（線被劃斷、墨點噴散、畫面一震）→ 巨大數字砸下**

### IG 版面

- 重要文字放在上下 250px 以內的安全區，右下角有按讚、留言按鈕
- 畫面上的字要能獨立說完故事（多數人靜音滑），有旁白也不一定要加字幕
- 旁白要貼著畫面上的字寫，靜音看字和開聲音聽的人拿到同一個故事

### 聲音

- 可以用程式合成音效（紙、筆、木頭、印章、和弦），不需要素材庫；質感比不上專業錄音
- 音效要跟視覺語言一致：紙與墨就用紙張摩擦、筆劃、木質敲擊，不用電子嗖嗖聲
- 手機喇叭放不出 100Hz 以下，低頻重擊要加中頻敲擊層才聽得到
- 旁白說話時把背景壓低約 11dB（ducking），人聲比背景大 12dB 以上才清楚

### 旁白

- 中文旁白每秒約 4–5 個字；先算字數再排時間
- 給 AI 語音的稿子，數字寫成中文字（「四萬」而不是「40,000」），避免念錯
- **旁白通常比預期長**：這次 30 秒的畫面配 33 秒的人聲，最後把畫面拉長到 39.5 秒
- 畫面劇情可以照旁白拉長，但粒子、水波要保持真實速度，才不會看起來變慢

### 技術與檔案

- 畫面寫成「時間的函數」（沒有累積狀態），就能逐格輸出、任意跳到某一秒檢查
- 先輸出幾張定格確認風格，再輸出完整影片，省時間也省 token
- 有逐格變化的顆粒會讓檔案暴增（crf 17 時 30 秒 106MB），要用固定位元率壓到約 5–7Mbps
- 傳給使用者的檔案上限 30MB
- 中文字體要本地字型檔注入，否則會退回系統字體

### 保險內容紅線

- 只用虛構家庭與假數字，不放客戶資料
- 不出現保費、保額、商品名、「一定理賠」「買了就沒事」
- 全程標示「虛構案例／示意」，結尾放不代表商品或給付承諾的聲明
- 公開前走公司審核流程

## 四、做「錢在工作」學到的事

成品評價：普通。主要原因是素材全部手搓、沒有參考影片、先做完整支才回頭補運鏡與質感。

- **技術上可行的**：從歌曲抓拍點、用重低音強度驅動震動、分鏡式運鏡（硬切／甩鏡／猛推猛拉）、甩鏡時加長快門做殘影
- **Blender 刻中文字不要用布林運算**：複雜字形會刻壞或整塊消失；改用「高度圖＋細密網格位移」推出刻痕，每個字都穩定
- **本機檔案的圖片會讓畫布無法讀取像素**：色彩錯位這類效果要用色版疊加，不要用讀像素的做法
- **只靠定格判斷不夠**：震動手感、剪接節奏需要有人看實際播放；每個驗收節點都要給含音樂的預覽
- 歌曲有版權：只在本機對拍，不進 repo；上傳 IG 時用不含歌的版本，從音樂庫加歌

## 五、下次的製作流程

參考：Threads @cooljerrett「Claude Opus 5.5 六步動畫工作流」。以下工具與效果是對方的說法，除了已註明的部分，都還沒在這個環境驗證。

### 六步對照

| 步驟 | 前兩支怎麼做 | 下次怎麼做 |
|---|---|---|
| 1. 找參考影片 | 沒有，只靠文字描述 | 先給 2～3 支參考影片，標出喜歡的秒數；抽幀分析剪接點、運鏡、字級、配色，照著目標做 |
| 2. 程式化輸出 | 有：自寫 Canvas 動畫，逐格輸出 MP4 | 保留，或改用 Remotion（React 寫每一幕，改一行就能重出）；Remotion 能不能在這個環境跑還沒驗證 |
| 3. 用現成資產 | 全部手搓：石紋、碎片、揚塵、背景都是程式算的 | 改用現成素材：免費授權的材質貼圖、實拍煙塵與碎片素材、專業字型；UI 類影片可用 21st.dev 的元件 |
| 4. 一次給足資料 | 只有文字需求，風格邊做邊定 | 開工前一次給齊：品牌色、字型、Logo、參考影片、素材、音樂；先要三個分鏡版本再挑 |
| 5. 靜態先行 | 有做定格，但放在後段 | 每一幕都先出關鍵畫面，全部通過才開始做動畫 |
| 6. 導演式指令 | 有來回修改，但多是「覺得普通」這類感受 | 用可操作的指令：「12.7 秒的甩鏡改硬切」「推近速度放慢到 0.7 倍」「這裡停 3 格」 |

### 開工前的資料包

- [ ] 參考影片 2～3 支，附上喜歡的秒數與原因
- [ ] 品牌色（或「交給 Claude」）、字型檔、Logo
- [ ] 文案或腳本
- [ ] 音樂檔（只用來對拍）與要用的片段
- [ ] 要用的素材：產品截圖、照片、材質、實拍素材
- [ ] 長度、比例、發布平台

### 導演指令用語

| 指令 | 意思 |
|---|---|
| 硬切 | 直接換到下一個畫面，沒有過渡 |
| 甩鏡 | 鏡頭快速橫甩到下一個位置，帶殘影 |
| 猛推／猛拉 | 在一兩格內突然放大或縮小 |
| 緩推／緩拉 | 慢慢放大或縮小 |
| 傾斜 | 畫面歪一個角度，增加不安感 |
| 速度 0.7 倍 | 這段動作放慢 |
| 停 N 格 | 畫面定住 N 格（30fps 時 1 格約 0.033 秒） |
| 對到第 N 拍 | 動作落在音樂的那一拍上 |

### 節奏

1. 資料包到齊 → 三個分鏡版本 → 挑一版
2. 每一幕一張關鍵畫面 → 逐張確認
3. 1～2 秒的風格樣片（含音樂）→ 確認動態與質感
4. 完整影片低解析度預覽（含音樂）→ 用導演指令修改
5. 正式輸出
